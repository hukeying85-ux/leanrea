# 下载小红书原图（2026-11-07 跑通）

把一篇小红书笔记里的**全部原图**、**原分辨率**、**不带水印**下载下来。

**结论一句话：别自己解析页面，直接用 GitHub 上的 `JoeanAmier/XHS-Downloader`。**
它用 `curl_cffi` 做浏览器 TLS 指纹伪装，官方说明 2.2 版起**无需 cookie** 就能取原图。
2026-11-07 实测：机房 IP、零 cookie、一条链接 7 张原图一次拿全。

---

## 一、为什么自己解析页面行不通

数据中心/机房 IP 裸请求小红书分享页，拿到的只有「游客壳」：

| 现象 | 数值 |
|---|---|
| 页面大小 | 恒定 236058 字节 |
| `__INITIAL_STATE__` | 只有 9865 字节的配置片段 |
| 图链数量 | **0** |
| `guestBrowsePolicy` | `{enabled:true, sources:["seo","direct"]}` |
| 接口返回 | `{"code":-101,"msg":"无登录信息，或登录信息为空"}` |

与链接形式无关（`/discovery/item/` 和 `/explore/` 返回完全一样），
与笔记新旧无关（早期能抓到的那一篇现在也抓不到了——是平台侧收紧）。

伪装 `Referer` 成 seo / direct 来源能把页面从 236KB 撑到 358KB，
state 从 9865 涨到 21084 字节，但里面**只有页脚的 ICP 备案信息，没有笔记内容**。

### 全部试过、确认不行的路子

| 方法 | 结果 |
|---|---|
| yt-dlp | `No video formats found!`（图文笔记没有视频格式） |
| gallery-dl | `rc=64 Unsupported URL` |
| r.jina.ai 文本代理 | 200 但只有 1.2KB，无图链 |
| Wayback Machine | 快照 0 条 / ReadTimeout |
| Playwright 真浏览器 | 页面渲染了，但 feed 接口回 `-101 无登录信息` |
| yt-dlp `--dump-json` | 只能拿到 1 张缩略图 |
| 伪装 seo / direct Referer | 拿到 358KB 页面，但图链只有备案 PDF |
| `gh secret` 配置 cookie | `HTTP 403 Resource not accessible by integration` |

## 二、可行的架构：GitHub Actions 中转

沙箱出网只放行 `github.com` / `pypi.org` 等少数域名，
但 **GitHub Actions 的 runner 出网不受限**。所以：

```
本地 push .mediaqueue/urls.txt
      ↓ 触发 .github/workflows/media-relay.yml
runner 跑 tools/media-library/relay_worker.py
      ↓ 结果 commit 到独立分支 media-out + 上传 artifact
本地 git fetch media-out 取回
```

### 操作步骤

1. 把链接写进 `.mediaqueue/urls.txt`（一行一条，`#` 开头是注释）：

   ```
   https://www.xiaohongshu.com/discovery/item/<笔记ID>?xsec_token=XXX&xsec_source=pc_share
   ```

2. 提交推送（push 到 `tools/media-library/**`、`.mediaqueue/**` 或工作流文件都会触发）：

   ```bash
   git add .mediaqueue/urls.txt && git commit -m "queue: ..." && git push origin <分支>
   ```

3. 等跑完（装 Chromium + pip 依赖，约 4–6 分钟）：

   ```bash
   RID=$(gh run list --workflow=media-relay.yml --limit 1 --json databaseId -q '.[0].databaseId')
   for i in $(seq 1 45); do
     S=$(gh run view $RID --json status -q .status); [ "$S" = "completed" ] && break; sleep 25
   done
   ```

4. 取回（默认 refspec 不含 `media-out`，必须显式 fetch）：

   ```bash
   git fetch -q origin +refs/heads/media-out:refs/remotes/origin/media-out
   git -c core.quotepath=false ls-tree -r origin/media-out --name-only   # 中文路径要关 quotepath
   git archive origin/media-out "media-raw/01_小红书素材/<slug>" | tar -x -C /tmp
   ```

## 三、核心：XHS-Downloader 怎么用

`tools/media-library/relay_worker.py` 里的 `try_xhs_downloader()`：

1. `git clone --depth 1 https://github.com/JoeanAmier/XHS-Downloader /tmp/xhsdl`
2. `pip install -r requirements.txt`（runner 的 Python 要 **≥3.12**，项目要求）
3. 调它的 `extract()`：

   ```python
   from source import XHS
   async with XHS(work_path="/tmp/xhsdl_dl", folder_name="Download",
                  cookie="", timeout=20, image_format="AUTO",
                  folder_mode=True, image_download=True,
                  video_download=False, download_record=False,
                  avg_delay=0.5, max_retry=3) as xhs:
       data = await xhs.extract(url, download=True)
   ```

   它自己会把文件下到 `/tmp/xhsdl_dl/Download/<笔记ID>/`，
   同时返回详情里带 `sns-img-bd.xhscdn.com/spectrum/...` 这样的原图直链
   （双保险，工具没下够时再按直链补一次）。

4. 落盘前**按内容 sha256 去重**、**按文件头确认是真图片**（见下）。

### 拿到的规格

| 项 | 值 |
|---|---|
| 域名 | `sns-img-bd.xhscdn.com/spectrum/...` |
| 分辨率 | 1440×3200（壁纸）/ 1600×1600（方图） |
| 单张体积 | 1.5–4.9 MB PNG |

## 四、踩过的坑（按重要性排序）

1. **Actions 日志读不到** —— `gh run view --log` 与 artifact 下载都在
   `results-receiver.actions.githubusercontent.com` / `*.blob.core.windows.net` 上 EOF。
   → **把诊断写成文件**（`media-raw/_debug/xhs_*.txt`），跟素材一起 commit 到 `media-out`，
   本地 `git show origin/media-out:media-raw/_debug/<文件>` 读。这是唯一可行的观测手段。

2. **页脚的营业执照 PDF 被当图存了** —— 页面 `ICPInfoList` 里有一堆
   `fe-video-qc.xhscdn.com/...pdf`，正则按域名捞就会中招（最大那个 9MB）。
   → 候选链接先过后缀黑名单，下载后**必须按文件头校验**
   （`_looks_like_image()`：JPEG/PNG/WEBP/HEIC/TIFF），PDF/HTML/XML 一律丢。

3. **工作流里的缩进 heredoc 会吞掉后面的命令** —— `<<'EOF'` 的终止符必须顶格，
   缩进写了就找不到，结果 `git add -A` 之后的整段静默不执行（发布步骤"成功"了但没提交）。
   → 清理逻辑放进 `tools/media-library/purge_nonmedia.py` 单独调用，别写 heredoc。

4. **内容 hash 去不掉工具下载 vs 直链下载的重复** —— 同一张图两条路拿到的字节不同
   （7 张存成 14 个文件）。→ 工具产出 ≥2 张就**不再走直链补下**。

5. **`run()` 返回 3 个值** —— `(rc, stdout, stderr)`，按 2 个解包会
   `ValueError: too many values to unpack`。

6. **结果分支是 `cp -r` 覆盖式同步，删不掉远端已有文件** —— 所以误存的垃圾
   要靠 `purge_nonmedia.py` 在发布步骤里按内容清一遍。

7. **Playwright 里 `JSON.stringify(window.__INITIAL_STATE__)` 会抛
   `Converting circular structure to JSON`** —— Vue 响应式对象带循环引用。
   → 每一步单独 `try`，DOM 图 / 渲染后 HTML / 接口响应各自独立生效，别让一处崩全链路。

8. **小红书 JSON 里的图片地址常是协议相对的** `//sns-webpic-qc.xhscdn.com/...`，
   正则写 `https?://` 会全部漏掉，要写 `(?:https?:)?//` 再补 `https:`。

9. **`__INITIAL_STATE__` 不能用正则抠到第一个 `</script>`**（必被截断），
   要用花括号配平（跳过字符串内的括号）。

10. **「下到 1 张就算成功」会掩盖失败** —— 缩略图也算 1 张，导致后面更好的工具不再接手。
    → 阈值设 `>= 2`。

11. **并发下载必须整套隔离** —— 队列是 `ThreadPoolExecutor(max_workers=3)` 并发的，
    XHS-Downloader 会在自己的 cwd 下写 `Volume/Temp`，多个笔记共用一份源码副本会
    互相删临时文件（`FileNotFoundError: .../Volume/Temp/<id>_2.auto`）。
    → 每篇笔记 `mkdtemp` 一份独立目录，并 `copytree` 一份独立源码；`pip` 安装提到
    线程池之前只跑一次，别让三个线程同时装依赖。

12. **扫描下载目录时别把源码副本一起扫了** —— 仓库里 `static/screenshot/*.png`
    有二十多张截图，混进来会让「7 张图」变成 32 个文件。
    → 下载固定落在临时目录的 `dl/` 子目录，只扫它。

13. **结果分支是镜像同步的，目录里留下什么线上就是什么** —— 所以每轮开跑前
    **先清空该笔记的目录**（`_reset_out_dir`），最后剩下的必然是这一轮真正下到的。
    只清「非图片」是不够的：改名前的旧 JPG、上一轮存重的副本会一直跟着。

## 五、发布同步

结果分支不能只 `cp -r`：它删不掉远端已有的文件，重复文件和早期残留会越积越多
（7 张图曾经被存成 14 个文件，旧笔记目录里混着上一轮的 18 个）。
现在用 `tools/media-library/publish_sync.py` 按「平台目录 / 笔记目录」逐层做镜像：
本轮没有的文件，在结果分支里直接删掉。

shell 里手写的同步循环不可靠（引号转义、`rsync` 有没有、源和目标写反都会静默出错），
**这类逻辑一律写成 Python 脚本调用**。脚本会把自己解析到的绝对路径和变更清单
写进 `media-raw/_debug/_publish.txt` —— Actions 日志读不到，只能这样取证。
