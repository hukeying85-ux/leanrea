# bio-teaching · 初高中生物学教学模块

> 一个 `SKILL.md` + 一个**总控对话** + 10 个**分模块对话** + 一套可验收的产物规格。
> 输入是一章教材（人教版初中 2024/2025 修订版、高中 2019 版），输出是一章的全套教学资产：
> **教材拆解 → 教学设计 → 讲解设计 → 课件 PPT → 习题检验 → AI 时代教学 → 逐字稿 → 视频演示 → 审校交付**。
> 延续本仓库的思路：不装 MCP、不加工具，也不把教材原文抄进仓库；Agent 用已有能力就能一章一章跑完。

## 一句话结论（先看这个）

**不要二选一。** 教材不适合整本丢给 `book-to-skills` 做"方法论蒸馏"（教材的价值是知识结构保真，不是可执行框架），
但 `book-to-skills` 的**分章切片 + 按需加载**机制正是我们要的底座。
所以采用两段式：**book-to-skills 负责"切章 + 抽结构"（原料层）→ 本模块的"教学指南"负责"可教性改写"（教学层）**。
判别表与理由见 [`references/conversion-route.md`](references/conversion-route.md)。

## 三个粒度，别混用

| 粒度 | 单位 | 谁用 | 判断标准 |
|---|---|---|---|
| 册 | 6–16 章 | 总控、排期 | 一学期 |
| **章** | 2–4 课时 | 教案、课件、习题、逐字稿 | **生产单位**：备案、交付、验收都按章 |
| **知识点** | 20–40 分钟 | 讲解设计、微课、诊断题 | **讲解单位**：能不能让一个学生在 40 分钟内真正懂 |

章是"要交什么"，知识点是"怎么讲好"。本模块把两者分开：`chapters/` 按章，`kp/` 按知识点。
跳过知识点直接做课件，产出必然是教材搬运——**02b 讲解设计**就是防这个的。

## 为什么按"章"切、一章一对话

一章 = 2–4 课时 = 一套资产 ≈ 一次对话的合理上下文预算。整册入上下文会稀释注意力，也会让产物互相污染（第 3 章的迷思概念混进第 1 章的课件）。
调度原则：**总控对话只做路由、状态与交接，不产出内容**；每一章由一条独立对话跑完 10 个模块，产物落盘后由 `scripts/check_chapter.py` 过 gate，再进入下一章。

## 怎么开始

```sh
# 1. 装依赖（只有 pptx 需要）
python3 -m pip install python-pptx

# 2. 打开总控对话，选一章，粘贴 prompts/00-教材拆解.md 开始
#    产物写进 chapters/<册>/<章>/
# 3. 一章做完跑验收
python3 scripts/check_chapter.py "chapters/高中-必修1-分子与细胞/第01章-走近细胞"

# 4. 重新生成本章课件
python3 scripts/build_pptx.py \
  "chapters/高中-必修1-分子与细胞/第01章-走近细胞/03-课件.md" --outdir /tmp/ch01
```

## 样板知识点：把"讲好"这件事做实

[`kp/必修1-第2章-蛋白质脱水缩合/`](kp/必修1-第2章-蛋白质脱水缩合/00-讲解设计.md) —— 一个 40 分钟的知识点，六份产物：

| 文件 | 是什么 | 关键点 |
|---|---|---|
| `00-讲解设计.md` | 七步协议的实例 | 20¹⁰⁰ 开场制造冲击；"两只手"一个类比撑到底；**公式靠数接缝数出来**，不先给 |
| `01-知识库卡片.md` | 结构化源（9 条命题 / 6 条迷思 / 6 个例题 / 边界 / 关联） | 下游全部从这里编译，改一处全局同步 |
| `02-教学指南.md` | 由卡片编译的教师用稿 | 40 分钟流程 + 板书六格 + 5 句关键话 + 4 道诊断题 |
| `03-学生一页学案.md` | 学生手上那张纸 | 先猜数、再画图、再数接缝、最后留一问 |
| `04-诊断题.md` | 8 题，错项即迷思 | 全班错项分布 → 下节课补哪里 |
| `05-板画与动画.md` | 板书六格 + 30 秒分镜 | 板画与动画共用同一套图元 |

**结论（这条最重要）**：以知识点为单位，**教材不是必需品**——机制、公式、变式、诊断题能从学科事实推出来，这套六份产物没有一页抄教材。但**章离不开教材**：顺序、深度边界、术语口径、入口情境都来自教材。所以本模块"以章为生产单位、以知识点为讲解单位"。

## 关于"上传到 Google Drive"

做了一次对比（同一个知识点，两条通道）：**直传 = 文件分发**，**知识库→编译指南 = 单一事实源 + 输出**。
打分 18 : 28，直传唯一胜在首建快（5 min vs 40–60 min）。结论：**Drive 上只放编译产物（指南 / 学案 / 诊断题），源（知识库卡）留在 git**，不要传 md 散件。
理由、打分表、复测方法见 [`references/drive-vs-kb-experiment.md`](references/drive-vs-kb-experiment.md)。

## 三条硬规则

1. **不把教材原文入库。** 只存"我们写的拆解与产物"；教材以学校配发或官方电子课本为准，引用处标注"章-节-栏目"而不抄页码原文。
2. **一章一对话，产物先落盘再进下一章。** 没过 gate 的章不写进 `chapter-map.md` 的 ready。
3. **AI 只做草稿，教师做终审。** 所有事实性内容须能在教材/课标/权威来源里指回证据；AI 生成的活动必须写清"学生要自己判断什么"。
