# three-view：从一条三视图笔记，到一套能用的角色参考资产

一个 `SKILL.md` + 两个脚本（`contact_sheet.py` 拼版 / `fetch_font.sh` 取中文字体），只依赖 Pillow 和生图工具。
延续本仓库 `leanrea/`、`healing-comic/` 的思路：不装服务、不加 MCP、每一步都有可验收的硬指标。

**核心原则：三视图的价值是「约束」，不是「好看」。** 一张参考图能锁住多少硬特征，下一轮 10 张就能少漂多少。
所以在动笔之前，先把原图拆成一张**可核对的角色卡**（第 2 步），再让每一张新图都挂着它生成。

**第二原则：能算的不要交给模型。** 拼版、编号、缩放、汇总图一律脚本做——模型画字会错、画对齐会歪，
而 Pillow 拼出来的 2×3 六视图是 100% 一致的。

## 何时用 / 何时别用

- 用：手上有别人做的三视图/设定图，想得到一套**同角色、同画风、可直接当参考图**的资产；做轻 IP 的形象规范；给下游生图准备「角色卡图」。
- 别用：要画剧情分镜（用 `healing-comic/`）；要精确配色规范书（用设计稿，不要用 AI）；需要商用授权但只有别人的图（先解决授权，见第 6 步）。

## 六步流程（本项目已完整跑通一轮）

```
S1 取源  →  S2 角色卡  →  S3 复刻六视图  →  S4 补视角  →  S5 拼版/预览  →  S6 交付/发布
 中继/本机    硬特征清单    01–06（挂原图）   07–09（挂 01/04）  10 汇总 / 11 预览    Drive + 文案
```

### S1 取源：先解决「图怎么进来」

沙箱（Arena/CI）出口通常只放行 GitHub / PyPI / npm，抖音、快手、B 站的 TLS 会被直接重置（`curl` 返回 `000`）。
三种可用的取图路线，按「要不要账号」排序：

| 路线 | 适用 | 命令 / 做法 |
|---|---|---|
| **中继下载**（本仓库 `tools/media-library/`） | 沙箱内、只要结果 | 把链接写进 `.mediaqueue/urls.txt` → push → GitHub Actions runner 出网抓 → 结果 commit 到 `media-out` 分支 |
| 签名直链 | 已经拿到了 CDN 直链（页面里能读到 `~tplv-…` 的图片地址） | 链接照样写进 `.mediaqueue/urls.txt`；worker 的 `direct-image` 通道按魔数校验后落盘 |
| 本机下载器 | 在用户自己机器上跑 | `douyin-downloader` / `f2`（需导 Netscape cookie）；见 `references/github-tools.md` |

中继的关键细节（都踩过）：

- 抖音 `/note/` 图文：`yt-dlp`、`gallery-dl` 都报 `Unsupported URL`；桌面页 HTML 里**一张图都没有**（JS 渲染）。
  所以要么走移动端分享页 JSON，要么直接喂签名直链。
- 图片直链带 `x-signature`，**去掉 query 就 403**，必须原样请求；`~tplv-…:q75.webp` 是压缩版，`~noop.jpeg` 才是原图变体。
- 结果落在 `media-raw/<平台目录>/<作品ID>/`，带 `meta.json`（来源、命中工具、逐文件 sha256）。
  复盘先看 `media-raw/_LAST_RUN.md`，失败原因逐条都写在那里。

### S2 角色卡：把「看起来像」变成「可以核对」

拿到源图后，先在 `references/character-spec.md` 里把**硬特征**写死。一张能用的角色卡至少四组：

1. **几何**：头身比、有没有脖子、脸和身体的边界弧线、四肢长度、站姿脚距。
2. **配色**（给十六进制，不要写「米白」）：body / 耳朵 / 内耳 / 描边 / 腮红 / 鞋。
3. **五官锚点**：眼睛形状与间距、嘴型（本项目是 `w`）、腮红位置与直径。
4. **可变项**：只有这 2–3 个能换（例如视角、道具），其余一律不许动。

再补两条「评论区真相」——原作者粉丝最清楚差异在哪。本项目实测有效：
`一二的耳朵是实心的，布布有内耳`；`一二穿深棕色鞋，布布光脚`；`两人除了颜色一模一样`。
这三条比任何形容词都管用，直接进了每一条提示词。

### S3 复刻六视图（01–06）

顺序固定：**先正面，再侧面，最后背面**，每张都把上一张挂成参考图（`images=[...]`）。

| 序号 | 内容 | 参考图 | 提示词要点 |
|---|---|---|---|
| 01 | 角色 A 正面 | 源图正面 | 全部硬特征 + 画布规则 |
| 02 | 角色 A 侧面（朝左） | 源图侧面 | 只露一只眼、一个腮红、尾巴小圆 |
| 03 | 角色 A 背面 | 源图背面 | 无脸、尾巴圆、**鞋要从后面能看见** |
| 04 | 角色 B 正面 | 源图正面 | 同一套提示词，只换配色与「有无鞋/结」 |
| 05 | 角色 B 侧面 | 源图侧面 | 内耳在侧视里最容易被画丢，单独强调 |
| 06 | 角色 B 背面 | 源图背面 | 背面没有内耳，别画出深色斑点 |

**画布规则（写进每一条提示词，别省）**：1:1 正方形、底色 `#F7F5F0`、主体高约 85% 居中、
描边等宽无渐变、`no text / no letters / no watermark / no shadow / no ground line`。

### S4 补视角（07–09）

- 07/08 **四分之三侧**：挂「正面 + 侧面」两张，明确说「转向观者左侧 45°」，远端耳/眼要变小。
- 09 **双人同框**：挂两张正面，写明「同一基线、等高、比例一致、中间留小缝」。这张最容易被画成一高一矮，写完比例再复查。

### S5 拼版与预览（10、11）

```sh
# 10 六视图汇总：2×3，无字，直接当参考图喂下游
python3 scripts/contact_sheet.py turnaround --indir examples/round-01 \
  --out examples/round-01/10_六视图汇总.png --cell 900

# 11 总预览：带编号 + 标题 + 来源脚注，交付/发布用
SHEET_FONT=~/.fonts/LXGWWenKaiLite-Regular.ttf python3 scripts/contact_sheet.py preview \
  --indir examples/round-01 --out examples/round-01/11_总预览.jpg \
  --title "一二布布 · 三视图复刻 10 张（第一轮）" \
  --note "源：抖音 @爱一二的布布《一二布布的三视图》6 张 · 01–09 AI 生成，10 脚本拼版"
```

`contact_sheet.py` 会先按四角底色**裁掉多余留白**再等比缩放，所以六张主体看起来一样大——手拼做不到这点。

### S6 交付与发布

- Drive 目录约定：源图直接放 `<素材 NN>/`，每轮成果放 `<素材 NN>/第X轮-…/`，一轮一个子目录。
- 一轮的完整交付物：`01–10` + `11_总预览.jpg` + `文案.md`（+ `SKILL.md` 副本，别人拿走就能复现）。
- 发布文案模板见 `references/copy-三视图-第一轮.md`：一句钩子 + 一句「怎么用」+ 3–5 个话题。
- **合规**：AI 生成图发布时要勾「AI 生成内容」标识；原图是别人的 IP，只做「风格学习/内部参考」，
  公开发布用自己重绘的版本，并在正文注明「参考自 @原作者 的三视图」。

## 一轮的实际节奏（10 张 = 生图额度上限）

生图工具单轮上限 10 次，所以「一轮」正好等于：**6 张六视图 + 2 张四分之三侧 + 1 张双人 + 1 张机动**，
汇总图与预览图由脚本出（不占额度）。若某张失败（一次性 500 或明显漂），用剩余额度重画那一张，
更常见的做法是**留到下一轮第一件事**补，别把整轮卡住。

## 失败模式（按出现频率）

| 症状 | 原因 | 处理 |
|---|---|---|
| 背面图发黄/发灰 | 模型把「背光」理解成「米色」 | 提示词里写死 `nearly pure WHITE (#FCFAF5), not beige` |
| 背面看不到鞋 | 背面被当成「无脚」 | 明确 `dark-brown flat shoes visible at the bottom` |
| 侧视画成 3/4 | 侧视提示词没锁「strict side profile」 | 加 `strict side profile facing LEFT`，并挂源图侧面 |
| 内耳丢 | 侧/背视里内耳信息少 | 侧视强调 `dark-chocolate inner oval`；背面强调 `no dark inner oval` |
| 双人一高一矮 | 同框没锁基线/等高 | `same baseline, exactly the same height` |
| 生图里出现中文/水印 | 模型自带排版冲动 | 负面词固定写全（no text/letters/watermark/shadow） |

## 四查清单（交付前 30 秒）

1. **数**：01–10 齐、11 预览里编号连续。
2. **色**：背面没变黄、布布没长鞋、一二没丢鞋。
3. **比例**：六视图主体在预览里等高；双人同框等高。
4. **字**：除了预览图上的标题/编号，图里一处文字都没有。
